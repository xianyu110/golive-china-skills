# 个人信息保护法隐私政策与用户协议 · PIPL Privacy Policy & Terms

> 属于 [golive-china-skills](https://github.com/xianyu110/golive-china-skills)。核对日期：2026-10-04。**本文与模板不是法律意见；上线前请由律师审阅。**

**English summary:** Generates a Chinese privacy policy and user agreement grounded in what your code actually collects. The agent scans the repo (forms, SDKs, permissions, analytics, logs, LLM calls), builds a data inventory, maps each item to PIPL notice requirements (Art. 17), flags items needing *separate consent* (sensitive data, sharing with third parties, cross-border transfer), and wires up a consent dialog + account deletion. A lawyer should review before publishing.

## 法律要点（已核对原文）

- **告知（个保法第十七条）**：处理前以显著方式、清晰易懂的语言真实、准确、完整告知：处理者名称和联系方式；处理目的、方式、种类、保存期限；个人行使权利的方式和程序等。[^pipl]
- **同意（第十三、十四条）**：同意应在充分知情前提下自愿、明确作出；法律要求单独同意或书面同意的从其规定；目的、方式、种类变更应重新取得同意。[^pipl]
- **需要"单独同意"的典型情形**（个保法相关条款）：向其他处理者提供个人信息、公开个人信息、处理敏感个人信息、向境外提供个人信息等。[^pipl]
- **不满十四周岁**未成年人的个人信息属于敏感个人信息，应取得监护人同意并制定专门处理规则。[^pipl][^data]
- **《网络数据安全管理条例》（2025-01-01 施行）第二十一条**：个人信息处理规则应集中公开、易于访问、置于醒目位置，并列明处理者名称和联系方式、目的方式种类、敏感个人信息的必要性和影响、保存期限、查阅复制转移更正补充删除等权利行使方式、注销账号和撤回同意的途径等。[^data]
- **App 场景认定标准**：《App 违法违规收集使用个人信息行为认定方法》列举了未公开规则、未明示目的、未经同意收集、超范围收集、未提供删除更正与注销功能等情形。[^rending]
- **推荐性国标** GB/T 35273-2020《个人信息安全规范》可作为写法参考。[^gbt]
- **跨境**：如果用户数据会传到境外（含调用境外大模型 API、境外云、境外统计 SDK），需评估《促进和规范数据跨境流动规定》等规定下的路径（安全评估/标准合同/认证/豁免），且告知与单独同意义务不因豁免而免除。[^xborder]

## 步骤

1. **数据盘点（agent）**：扫描仓库，输出 `data-inventory.md`：

| 信息类型 | 来源（代码位置） | 目的 | 是否必要 | 敏感？ | 保存期限 | 共享给谁/SDK | 是否出境 |
|---|---|---|---|---|---|---|---|

   重点找：注册表单、手机号/验证码、支付回调里的用户标识、日志（IP、UA）、埋点/统计 SDK、崩溃上报、地图定位、相册/相机、推送、客服 SDK、**发给大模型的用户输入**。
2. **合规映射（agent）**：对每行标注所需告知内容与是否需单独同意；标出"非必要却默认收集"的项建议删除或改为可选。
3. **起草（agent）**：用 `templates/privacy-policy-template.md` 和 `templates/user-agreement-template.md` 填充，不写代码里不存在的处理活动，也不漏写存在的。
4. **产品落地（agent）**：
   - 首次启动/注册前弹出隐私政策摘要 + 链接，**不默认勾选**，拒绝后提供基本浏览或退出；
   - 设置页常驻"隐私政策""用户协议""个人信息收集清单""第三方共享清单"；
   - 账号注销入口与后端删除/匿名化逻辑；权利请求（查阅、复制、更正、删除）响应渠道；
   - 敏感权限（定位、相册、通讯录）在使用时再申请，并说明用途。
5. **律师审阅（human）**：确认主体、联系方式、保存期限、出境安排、未成年人政策。
6. **发布与版本管理（agent）**：政策页显示生效日期与版本；重大变更重新取得同意。

## 检查清单

- [ ] 处理者名称、联系方式（含个人信息保护负责人联系方式，如适用）
- [ ] 每类个人信息的目的、方式、范围、保存期限
- [ ] 第三方 SDK / 共享方清单（名称、目的、信息类型、隐私政策链接）
- [ ] 敏感个人信息单列并说明必要性与影响，取得单独同意
- [ ] 不满 14 周岁未成年人规则与监护人同意
- [ ] 权利行使方式、注销账号与撤回同意途径、响应时限（如有承诺须能做到）
- [ ] 是否出境及所采用路径；调用境外模型 API 时尤其注意
- [ ] AI 生成内容的标识方式写进用户协议（见 `genai-algorithm-filing`）
- [ ] 首次同意弹窗不默认勾选；入口易于访问
- [ ] 政策内容与代码实际行为一致（上线后每次加 SDK 都要更新）

## 常见被拒/被通报原因与修复

| 原因 | 修复 |
|---|---|
| 无隐私政策或首次运行未提示 | 增加首次启动弹窗与常驻入口[^rending] |
| 政策写了"可能收集"等模糊表述 | 逐项写明目的与范围 |
| 收集与功能无关的信息 / 强制授权 | 去掉非必要收集，拒绝后不影响基本功能 |
| 第三方 SDK 未披露 | 补 SDK 清单 |
| 无注销功能或注销设置障碍 | 提供注销入口并实际删除/匿名化 |
| 小程序隐私指引与代码不一致 | 见 `wechat-miniprogram-launch` |

## Agent 能做 vs 人必须做

| Agent | 人（+ 律师） |
|---|---|
| 扫描代码生成数据清单、SDK 清单 | 确认业务目的、保存期限、出境安排 |
| 起草政策/协议、实现同意弹窗与注销 | 律师审阅、对外发布、承担责任 |
| 每次 PR 检查"新增收集行为"是否已更新政策 | 回应用户权利请求、监管问询 |
